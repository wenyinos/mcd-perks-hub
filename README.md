## 为什么需要它

麦当劳的券**不是"某日截止"这么简单**。实测真实券：

```
tradeTimePeriods: [{"startTime": "05:00:00", "endTime": "10:29:59"}]
weekdays:         [1]                     # 周日
tradeStartDateTime: "2026-10-11 05:00:00"
tradeEndDateTime:   "2026-10-11 10:29:59"
```

**含义：只在 10-11（周日）05:00-10:29 之间可用。**

于是常见的损失不是"忘了用"，而是：

- ❌ 券还在有效期内，**但当天的时段已经过了**
- ❌ 记得今天能用，**但不知道只剩 20 分钟**
- ❌ 早餐券躺了 10 天，**每天醒来都错过 10:29 这个坎**

传统提醒工具只告诉你"哪天过期"，**漏掉了时段维度**——提醒了，照样用不上。

本 Skill 的核心是 **「权益可用窗口」模型**：把有效期解析为
`日期 × 每日时段 × 星期约束` 的三维窗口，输出三态与精确倒计时。

## 功能一览

| 功能 | 说明 |
|---|---|
| 🔥 **窗口三态判定** | 进行中 / 未到 / 已错过，精确到分钟 |
| ⏰ **P0~P3 优先级** | 按"最快就要错失"排序，不是按券名 |
| 💰 **待领取盘点** | 麦麦省可领券按状态过滤，避免重复推荐 |
| 📈 **积分过期预警** | 本月 / 下月将过期积分 + 商城兑换建议 |
| 🎰 **抽奖与奖品** | 服务端资源判定直读，可用奖品倒计时 |
| 📅 **活动日历** | 当月进行中 / 未来活动，与持有券交叉 |
| 🧮 **用券算价** | 双轨对比，量化"省多少"（按需） |
| ✅ **写操作确认制** | 领券 / 抽奖 / 下单均需显式同意 |

## 快速开始

### 1. 申请 MCP Token

1. 打开 <https://open.mcd.cn/mcp>
2. 右上角【登录】→ 手机号验证
3. 点【控制台】→【激活】→ 同意服务协议
4. 一键复制 Token

### 2. 配置 MCP 连接

把 `mcp-config.example.json` 中的 `${MCD_MCP_TOKEN}` 换成你的 Token：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

**⚠️ 不要把真实 Token 提交到仓库。** 推荐用环境变量：

```bash
export MCD_MCP_TOKEN="你的Token"
```

### 3. 运行

```bash
# 无需第三方依赖，Python 3.9+
python3 scripts/perks_scan.py              # 《今日权益行动清单》
python3 scripts/perks_scan.py --json       # 结构化 JSON（便于二次开发）
python3 scripts/perks_scan.py --no-verify  # 跳过商城校验，省配额
python3 scripts/perks_scan.py --out report.txt   # 写入文件

# 单元测试
python3 tests/test_expiry_scorer.py
```

### 4. 作为 Skill 使用（WorkBuddy / Cursor / Cherry Studio 等）

把 `skills/mcd-perks-hub/` 目录注册为 Skill，或直接将 `SKILL.md` 作为系统提示词加载。
之后用自然语言提问即可：

> 「帮我看看今天麦麦有什么该用的」
> 「我的券今天几点能用？」
> 「券快过期了，怎么用掉最值？」

## 技术亮点

### 1. 把易错的时间计算从 LLM 手里拿走

大语言模型推算"距离 10:29 还有多少分钟""跨日窗口怎么算"极易出错。
本项目把全部时间逻辑下沉到 `expiry_scorer.py`，**结果是确定性的**，可单测。

### 2. 结构性适配，而非硬编码

实测发现麦当劳 MCP 有若干"反直觉"细节，全部做了显式适配：

| 坑 | 适配 |
|---|---|
| 数值字段是**字符串**（`"472.1"`） | 统一 `_num()` 转换 |
| 字段拼写是 `Mouth` 不是 `Month` | 照抄，不做"纠正" |
| `weekdays` 编号 **周日=1**（与 Python 相反） | `_w2py()` 显式转换 + 单测 |
| `available-coupons` 用 `couponStatus` 而非 `status` | 按实际字段判定 |
| 券同时返回结构化 + Markdown 文本 | 结构化优先，文本兜底 |

完整清单见 [MCP_INTEGRATION.md](MCP_INTEGRATION.md#4-实测踩坑与适配本项目工程价值所在)。

### 3. 零第三方依赖

纯 Python 标准库实现，克隆即可运行，无安装负担。

### 4. 写操作全程人工确认

领券、抽奖、下单均需用户显式同意，一次只做一件。**不做任何自动化批量操作。**

## 常见问题

**Q：为什么我的券显示"未到"而不是"可用"？**
A：麦当劳的券常有每日时段限制（如早餐券 05:00-10:29）。若当前不在时段内，
工具会告诉你窗口何时开启，而不是笼统地说"有效期内"。

**Q：调用会消耗配额吗？**
A：单次完整盘点约 6~7 次调用；限流为 600 次/分钟，日常使用无压力。
`--no-verify` 可再省去商城查询。

**Q：Token 安全吗？**
A：Token 只从环境变量读取，不会写入任何文件、不会出现在日志中。
仓库中仅保留 `${MCD_MCP_TOKEN}` 占位符。

**Q：支持外送场景吗？**
A：支持。`query-my-coupons` 返回的 `orderTypes` 区分到店(1)/外送(2)，
本地判定会结合券的渠道限制给出建议。
